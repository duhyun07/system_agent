# Security model

System Agent is a kernelCTF research platform. Its deliverable is evidence-backed root-cause analysis, triage, crash deduplication, and reporting. It does not implement or automate privilege escalation, persistence, kernel-protection bypass, or exploit-chain development, and it does not generate exploit code. Research operates on authorized local kernel checkouts and, for dynamic tests, on approved isolated VMs only.

System Agent treats repository files, kernel source, crash logs, fetched pages, and search snippets as untrusted evidence. The system prompt tells models to ignore embedded instructions, but authorization is enforced in Python. Skills are exposed to a model only when policy permits them. A model cannot alter workspace roots, allowlists, approval state, timeouts, or limits through skill arguments.

Phase isolation: the workflow state machine (`core/state_machine.py`) enforces the Online-setup → Offline-research progression. Once in the `OFFLINE_RESEARCH` phase, the machine never transitions back to an online phase automatically — a failure is never a reason to go back online. Re-entering setup is an explicit user action (`reset_online`). Offline research additionally runs with all network skills removed from the offered tool set, independent of the mode allowlist, so a research task cannot reach the network even if the mode's allowlist is non-empty.

Filesystem access uses authorized roots, rejects traversal and protected paths, and opens each directory component with `O_NOFOLLOW`. File reads and writes refuse symlinks. Writes use a temporary file in the target directory, `fsync`, and atomic replacement. Exact edits and patches require approval and expected file hashes. A multi-file patch validates every file before writing; its individual replacements are atomic, but the group is not a single filesystem transaction.

Network access is disabled in Offline mode. In Online and Hybrid, destinations require exact or explicitly wildcarded domain allowlisting. IP literals, nonstandard ports, private, loopback, link-local, reserved, and metadata addresses are rejected. DNS resolution is checked before each request and redirect; the connection is pinned to the checked IP. HTTPX runs with environment proxies disabled and TLS verification enabled. No caller-supplied headers are exposed through the `fetch` skill. Search provider credentials are sent only to the fixed Brave API endpoint, and credential-bearing requests cannot redirect.

Hybrid cloud calls consume one-use approval bound to the SHA-256 of the exact serialized task payload. Hybrid network skill calls also consume one-use approval for exact arguments. Offline and Hybrid research use local Ollama unless an explicit cloud task is approved. Do not treat a displayed SHA-256 alone as meaningful consent without reviewing the corresponding payload and diff.

Dynamic testing is tightly constrained. The `kernel_test_run` skill is CLI-only (never offered to or callable by the model), requires one-use approval bound to its exact arguments, refuses to run unless the caller explicitly confirms VM isolation, runs only a researcher-provided executable harness inside an authorized workspace (never model-generated code and never a shell string), and applies a wall-clock timeout plus best-effort CPU/address-space rlimits with bounded captured output. WSL alone is not treated as a sandbox; risky dynamic experiments require a separate isolated VM. Host-kernel fuzzing is out of scope, and the syzkaller adapter is read-only (it summarizes an existing authorized run and never launches fuzzing).

Original crash evidence is immutable: `FindingsStore.store_crash_evidence` writes each raw log once under `evidence/crashes/<sha>.log` with mode `0444` and `O_EXCL`, so a finding's cited evidence cannot be silently altered. Findings default to `hypothesis`/`not_tested`; the store refuses to mark a finding `validated` without a `reproduced` validation record.

For static scans of untrusted research material, `scripts/run-isolated.sh` adds Docker OS isolation: no network, read-only research mount and root filesystem, no capabilities, no privilege gains, and CPU, memory, and process caps. The container image must be built separately. This isolated runner cannot use Ollama or mutate files. The ordinary CLI relies on application-level checks and should run under a dedicated low-privilege account for sensitive work.

Audit events in `logs/audit.jsonl` record tool name, task/origin, argument and result hashes, status, and duration. They do not contain tool arguments or result contents. Protect the log directory with ordinary filesystem permissions. No API key values are logged.

Known limits: cross-process edits can race between the final hash check and rename; use a dedicated workspace or external file locking if multiple writers share a tree. Spending estimates use configured token prices and a conservative token approximation, and real provider bills may differ. Containerized isolation requires Docker and was not exercised in the default unit tests. The project does not execute downloaded content or provide an unrestricted shell skill.
